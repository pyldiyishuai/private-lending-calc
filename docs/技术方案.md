# 民间借贷利息计算器 · 技术方案

---

## 一、产品定位

### 用户是谁

| 画像 | 场景 | 核心诉求 |
|---|---|---|
| 借款人 | 收到律师函，说欠 30 万 | 到底该还多少 |
| 借款人 | 已还了一堆钱仍说没还清 | 有没有多付 |
| 出借人 | 想主张利息 | 能支持多少 |
| 担保人 | 被追偿 | 我要承担多少 |
| 家属 | 帮家人处理 | 这些费用合法吗 |

### 为什么这个需求值钱

1. **金额大**：民间借贷单笔通常 10 万–500 万
2. **信息极度不对称**：多数人不知道有四倍 LPR 上限，更不知道砍头息不算本金
3. **计算有确定性**：规则清晰、可验证，工具的可信度容易建立
4. **法律服务 CPC 极高**：债权债务律师获客成本 ¥80–500/条
5. **搜索全年稳定**：借钱不受季节影响

## 二、算法结构

### 2.1 三个关键判断

```
判断 1：合同成立日 vs 2020-08-20
  ├─ 之后 → 新规：上限 = LPR(合同日) × 4
  └─ 之前 → 旧规：24% 保护 / 24–36% 自然债务 / >36% 无效

判断 2：砍头息
  └─ 实际本金 = 账面本金 − 砍头息（《民法典》670 条）

判断 3：约定利率 vs 上限
  ├─ ≤ 上限 → 合法利息 = 约定利息
  └─ > 上限 → 合法利息 = 本金 × 上限 × 年数，差额不受保护
```

### 2.2 LPR 的时间点问题

这是最容易做错的地方。**必须用合同成立时的 LPR**：

```js
// ✅ 正确
var lpr = lprAt(startDate);

// ❌ 错误：用了今天的 LPR
var lpr = lprAt(todayStr());
```

原因：四倍 LPR 规则的本意是「签约时双方能预期的上限」。
如果按起诉时的 LPR 算，等于让司法行为改变合同内容。

**实务中的争议**：LPR 规则出台后，2020-08-20 之前成立的合同
如何衔接，各地法院掌握不完全一致。多数做法是**分段计算**：
2020-08-20 之前按 24%/36%，之后按四倍 LPR。

### 2.3 合法性上限的取 min

```js
var cappedRate = Math.min(rate, effectiveCap);
var legalInterest = principal * cappedRate * years;
```

如果约定 12%、上限 14.6%，合法利息就是按 12% 算的。
写成 `principal * effectiveCap * years` 会让合法利息**高于**约定利息，
逻辑上荒谬，但很容易写错（本项目初版就踩了这个坑）。

### 2.4 复利的年数

```js
years = diffDays(start, end) / 365;
```

不能用 `endDate.getFullYear() - startDate.getFullYear()`——
三年里可能含一个闰年，实际 1096 天 = 3.0027 年。
单利下误差可忽略，复利会放大。

### 2.5 旧规的两线三区

| 区间 | 效力 | 处理 |
|---|---|---|
| 0–24% | 完全保护 | 全额支持 |
| 24%–36% | 自然债务 | 已付不退，未付不支持 |
| >36% | 无效 | 已付可要求返还 |

注意 24%–36% 不是「不支持」，而是「法院不强制但也不否定」——
这个区别在写提示文案时要准确表达。

## 四、扩展点

### 4.1 跨 2020-08-20 分段计算（优先）

**场景**：2019 年借的钱，2021 年才结算。

**规则**：分两段。
- 2019-06-01 → 2020-08-20：按旧规（24% 上限）
- 2020-08-20 → 2021-06-01：按新规（当时 LPR × 4）

**已有**：`splitPeriod()` 函数已实现雏形，但没接 UI。
**改哪里**：`ui/result.js` 加一个分段表。

### 4.2 违约金与罚息合并

**规则**：利息 + 复利 + 罚息 + 违约金 + 其他费用，
**总和**不得超过四倍 LPR。

**实现**：在 `buildResult` 里加 `penalty` 输入，
合并计算后与上限比对，而不是各自比对。

**这是实务中最常见的争议点**：出借人常把利率压到 12%，
再另加 10% 违约金，实际 22% 但形式上看不出来。

### 4.3 分期还款明细

**场景**：借 10 万，每月还 5000，还了 18 个月。

**难点**：每笔还款要先抵利息还是先抵本金，结果差很多。
- 先息后本：剩余本金下降慢
- 先本后息：利息算得少

**实现**：逐期摊还表，每期显示「还款额 / 抵利息 / 抵本金 / 剩余本金」。

### 4.4 证据清单自检

**内容**：一个勾选清单，帮用户判断自己的证据够不够。

- [ ] 借条 / 借款合同
- [ ] 转账记录（银行流水）
- [ ] 聊天记录提到「借」「还」
- [ ] 通话录音
- [ ] 对方还过款的记录
- [ ] 催收记录（证明时效中断）

**价值**：这是「内容型工具」，比计算器更容易被分享。

### 4.5 律师线索（核心变现）

**已有**：`APP.FEATURES.lawyerLead`、`#leadBox`、`leadSubmit`。

**触发条件**：`principal >= 50000 || excess >= 10000`。
金额太小的案子律师不接，反而拉低线索质量。

**质量信号**：
- 是否已收到起诉状 / 律师函（进入诉讼阶段，价值最高）
- 是否有砍头息（争议明确，胜诉率高）
- 是否已还清（已付超额的返还请求）

### 4.6 诉讼费计算

**规则**：按标的额分段累计（1 万以下 50 元，1–10 万 2.5%，…）。

**价值**：用户起诉前最想知道「要花多少钱」。
实现简单，可以直接加在结果页。

## 五、SEO 策略

### 5.1 关键词结构

```
核心：民间借贷利息计算器
  ├── 规则词：四倍LPR / LPR四倍是多少 / 民间借贷利率上限
  ├── 概念词：砍头息 / 利滚利 / 服务费算不算利息
  ├── 纠错词：借钱利息多少合法 / 高利贷标准 / 利息超过多少不受保护
```

### 5.3 内容角度

这个赛道的用户分两类，内容要分开写：

**借款人视角**：《我被收了 36%，合法吗》《已经还了 3 年，能要回多付的吗》
**出借人视角**：《借出去的钱怎么主张利息》《对方不还，起诉要准备什么》

大多数流量是借款人，但**出借人的转化率更高**（他们主动要打官司）。

## 八、已知坑

### 坑 1：合法利息忘了取 min

```js
var legalInterest = principal * effectiveCap * years;          // ❌
var legalInterest = principal * Math.min(rate, cap) * years;   // ✅
```

约定 12%、上限 14.6% 时，前者会算出比约定利息还高的「合法利息」，
逻辑上不成立。本项目初版就踩了这个坑，测试才发现。

### 坑 2：LPR 用了今天的

必须用合同成立日的。这是整个工具的核心逻辑，
写错了所有结果都是错的。

### 坑 3：复利年数按整年算

`(end - start) / 365` 才对。三年含闰年是 3.0027 年。

### 坑 4：24%–36% 不等于「不支持」

自然债务区的法律效果是「已付不退、未付不支持」。
写文案时说成「不受保护」会让人误以为已付的能要回来。

### 坑 5：format.js 缺 moneyFree

从其他项目 scaffold 来的 `format.js` 只有 `money()`（自动转万元）。
明细表必须用固定元显示，否则 ¥95,000 会变成「9.5 万」，
用户没法对照转账记录。

### 坑 6：快捷选项的 is-on 状态要自己维护

`data-quick-rate` 这类按钮不是原生 radio，
点击后要手动切换所有兄弟按钮的 `is-on` 类，
否则会出现多个按钮同时高亮。
